ENTENDA O BÁSICO

O que são Git e GitHub?

⏱

Git

É um sistema de controle de versão. Ele registra as mudanças feitas nos arquivos de um projeto e permite consultar versões anteriores.

Pense nele como um histórico organizado de tudo o que mudou em um trabalho.

☁

GitHub

É uma plataforma online que hospeda repositórios Git. Ela facilita guardar projetos na internet, compartilhar arquivos e colaborar com outras pessoas.

É como uma área de trabalho online para organizar e compartilhar projetos.

Resumindo: Git é a ferramenta de controle de versões; GitHub é uma plataforma que utiliza Git e oferece recursos de colaboração online.

O que é um repositório?

É o espaço onde ficam os arquivos de um projeto e seu histórico de alterações.

PÚBLICO

Visível para todos

Qualquer pessoa pode visualizar o conteúdo. É útil para divulgar projetos e materiais abertos.

PRIVADO

Acesso restrito

Somente o proprietário e as pessoas autorizadas podem acessar o conteúdo. É indicado para trabalhos que não devem ficar abertos ao público.

PALAVRAS IMPORTANTES

Conheça as funções do GitHub

Estes são os principais recursos que você precisará conhecer para realizar a atividade.

R

README

Arquivo de apresentação do repositório. Explica o objetivo do projeto, seus conteúdos e como utilizá-lo. Geralmente é escrito em Markdown.

M

Markdown (.md)

Uma forma simples de formatar textos usando símbolos. Por exemplo, # Título cria um título e **negrito** destaca uma palavra.

C

Commit

É um registro de uma alteração no repositório. Cada commit deve ter uma mensagem clara, como “Adiciona explicação sobre README”.

H

Histórico de alterações

Mostra os commits realizados, permitindo identificar quem fez cada alteração e quando ela foi registrada.

B

Branch (ramificação)

É uma linha de trabalho separada da principal. Permite fazer melhorias sem alterar imediatamente a versão principal.

P

Pull Request (solicitação de alteração)

É uma proposta para revisar e incorporar mudanças de uma branch em outra. Os colegas podem analisar e comentar antes da aprovação.

M

Merge (mesclagem)

É a união das alterações de uma branch com outra, por exemplo, incorporando uma melhoria à branch principal.

COMECE A USAR

Como criar seu primeiro repositório

Você pode realizar estes passos pelo navegador, sem instalar o Git e sem usar o terminal. Clique em cada etapa para assistir à explicação em vídeo.

  1. 1
    Crie ou acesse sua conta Entre em github.com e faça login. Se ainda não tiver conta, escolha a opção de cadastro.

    Vídeo explicativo: como acessar ou criar uma conta no GitHub.

  2. 2
    Crie um repositório Clique no sinal de + e escolha New repository. Dê um nome, escolha público ou privado e clique em Create repository.

    Vídeo explicativo: criando seu primeiro repositório.

  3. 3
    Crie o README.md Crie o arquivo README.md, escreva a apresentação do projeto e salve usando Commit changes.

    Vídeo explicativo: criando e editando o README.

  4. 4
    Adicione ou envie arquivos Use Add file → Create new file para criar um arquivo ou Upload files para enviar arquivos do computador.

    Vídeo explicativo: adicionando arquivos ao repositório.

  5. 5
    Consulte o histórico Acesse o histórico de commits para visualizar as mensagens, os autores e as alterações registradas.

    Vídeo explicativo: consultando o histórico de alterações.

Dica: o GitHub pode mudar alguns nomes ou posições dos botões. Se a tela estiver diferente, procure as opções equivalentes de criação de arquivo, envio e commit.

TRABALHO EM EQUIPE

Como colaborar em um projeto

Aprenda a trabalhar com outras pessoas utilizando os recursos de colaboração do GitHub. Clique em uma etapa para assistir ao vídeo correspondente.

01 Convide colaboradores Abra o repositório, vá em Settings → Collaborators, clique em Add people e procure o usuário GitHub do colega.

Vídeo explicativo: convidando pessoas para colaborar.

02 Crie uma branch Crie uma nova ramificação chamada melhoria-guia, partindo da branch principal.

Vídeo explicativo: criando uma branch.

03 Faça uma alteração e um commit Abra um arquivo na branch, faça uma melhoria e registre a mudança com uma mensagem objetiva.

Vídeo explicativo: editando arquivos e criando commits.

04 Abra um Pull Request Crie uma solicitação para comparar sua branch com a principal e permitir que outras pessoas revisem a mudança.

Vídeo explicativo: criando um Pull Request.

05 Faça o Merge Depois da revisão, incorpore as alterações à branch principal utilizando Merge pull request.

Vídeo explicativo: realizando o Merge.

PUBLIQUE COM ATENÇÃO

Cuidados ao compartilhar arquivos

Antes de publicar

  • Confira se o arquivo pode ser compartilhado.
  • Não publique senhas, tokens ou códigos de autenticação.
  • Oculte dados pessoais nas capturas de tela.
  • Revise o conteúdo e os links.

Durante a colaboração

  • Convide apenas as pessoas necessárias.
  • Não compartilhe sua senha.
  • Use mensagens de commit claras.
  • Revise as alterações antes do merge.
